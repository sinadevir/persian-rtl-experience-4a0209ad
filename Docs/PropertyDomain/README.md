# راهنمای مستندات PropertyDomain.WebApi

این پوشه فقط اسناد مرجع تولیدشده در مراحل D01 تا D04 را نگهداری می‌کند. متن توضیحی مستندات فارسی است؛ شناسه‌ها و نام‌های فنی برای تطبیق با کد انگلیسی باقی می‌مانند.

## نقشه مستندات

| موضوع | مسیر | کاربرد |
|---|---|---|
| معماری کلان | `Architecture/` | سبک معماری، مرز ماژول‌ها و تعاملات |
| مستندات ماژول‌ها | `../Modules/*/README.md` و `Modules/` | مسئولیت، مفاهیم، قواعد و API هر حوزه |
| API | `API/` | مسیرها، پارامترها، پاسخ‌ها و مجوزها |
| فرهنگ داده | `DataDictionary/` | Schema، جدول، ستون، نوع SQL، کلید و قید |
| یکپارچه‌سازی | `Integration/` | پیام‌ها، نسخه‌ها، Outbox/Inbox و مسیر‌یابی |
| گزارش مراحل مستندسازی | `Documentation/` | خروجی D01 تا D04 |
| پایگاه داده | `../Database/` | خط مبنا، اسکریپت تجمیعی تغییرات و Seed |
| آزمون‌های SQL | `../Tests/Database/` | اسکریپت‌های اجرایی راستی‌آزمایی |

## وضعیت مراحل

- D01 ـ ممیزی شکاف مستندات: `Documentation/گزارش-ممیزی-مستندات-نسخه-11.8.md`
- D02 ـ معماری کلان: `Architecture/01-معماری-کلان-سامانه.md`
- D03 ـ مستندات ماژول‌ها: `Modules/README.md` و README هر ماژول
- D04 ـ API، فرهنگ داده و قراردادهای یکپارچه‌سازی: `API/`، `DataDictionary/` و `Integration/`

## قاعده صحت

هر ادعا باید به کد، DDL یا قرارداد قابل ردیابی باشد. قابلیت پیاده‌سازی‌شده، مورد طراحی‌شده اما پیاده‌سازی‌نشده و تصمیم باز باید از یکدیگر تفکیک شوند. وجود Entity، جدول یا Route به‌تنهایی به معنی تکمیل گردش‌کار کسب‌وکاری نیست.
