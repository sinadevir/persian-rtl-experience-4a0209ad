# B03 ـ قراردادهای یکپارچه‌سازی ملک و ساختار فیزیکی

**وضعیت:** قرارداد سمت تولیدکننده برای پیوندهای زمانی ساختار ملک. در این نسخه، وجود مصرف‌کننده پایین‌دستی B03 فرض یا پیاده‌سازی نشده است.

## مرز مسئولیت‌ها

- B03 مالک هویت Premises، کاتالوگ‌های Parcel، Building و Unit و روابط ساختاری زمان‌مند است.
- B02 مالک سوابق حقوقی مالکیت و تصرف است؛ پیوند ساختاری B03 به‌تنهایی مالکیت یا تصرف را اثبات نمی‌کند.
- B04 مالک UsageSegment و تخصیص‌های قانونی/عملیاتی کاربری است؛ رویداد ساختاری B03 طبقه‌بندی کاربری را اثبات نمی‌کند.
- B05 مالک هویت Customer و ارتباط‌های مشترک است؛ رویداد B03 به معنی ایجاد ارتباط Customer نیست.
- B07 فقط از طریق قرارداد Projection جداگانه و توافق‌شده می‌تواند وقایع Timeline بسازد؛ ورودی فعلی رویدادهای Customer در B07 مصرف‌کننده رویداد B03 نیست.

## پوش پیام

پیام‌ها از `IntegrationEnvelope<T>` مشترک با `schemaVersion=1` و JSON به صورت camelCase استفاده می‌کنند: `messageId`، `messageType`، `sourceDomain`، `schemaVersion`، `occurredAt`، `correlationId`، `causationId` و `data`. مقدار `sourceDomain` برابر `B03` است. `messageId` در تلاش‌های مجدد ثابت می‌ماند. `occurredAt` و `recordedAt` زمان ثبت هستند؛ `validFrom` و `validTo` زمان اعتبار کسب‌وکاری را نشان می‌دهند.

## `PremisesStructureLinkChanged`

این پیام پس از ایجاد موفق یا پایان یکی از پیوندهای زمان‌مند زیر منتشر می‌شود:

- `PremisesParcel`
- `PremisesBuilding`
- `PremisesUnit`
- `ParcelBuilding`
- `BuildingUnit`

| فیلد | نوع | معنا |
|---|---|---|
| `tenantId` | int64 | مرز Tenant |
| `relationType` | string | یکی از پنج نوع رابطه بالا |
| `action` | string | `Added` یا `Ended` |
| `linkId` | int64 | شناسه ردیف رابطه زمان‌مند |
| `premisesId` | int64/null | سر رابطه Premises در پیوندهای مستقیم |
| `parcelId` | int64/null | شناسه Parcel در صورت ارتباط |
| `buildingId` | int64/null | شناسه Building در صورت ارتباط |
| `unitId` | int64/null | شناسه Unit در صورت ارتباط |
| `relationRole` | byte | نقش ذخیره‌شده رابطه؛ معنا از مرجع داده B03 تعیین می‌شود |
| `validFrom` | datetime | ابتدای بازه اعتبار، شامل ابتدا |
| `validTo` | datetime/null | انتهای بازه اعتبار، خارج از بازه؛ null یعنی باز |
| `recordedAt` | datetime | زمان ثبت ردیف پیوند |
| `actorId` | int64/null | عامل انجام عملیات، در صورت وجود |

این پیام فقط رابطه ساختاری را توصیف می‌کند. نباید به‌عنوان تغییر مالکیت، تصرف، کاربری یا ارتباط مشترک تفسیر شود. مصرف‌کننده‌ای که به ساختار کامل جاری/تاریخی نیاز دارد باید از قرارداد خواندن نسخه‌دار B03 استفاده کند؛ یک رویداد به‌تنهایی Snapshot کامل نیست.

## تحویل و مسیریابی

- تحویل حداقل یک‌بار است؛ مصرف‌کننده باید بر اساس `(tenantId, consumerName, sourceDomain, messageId)` تکرار را حذف کند.
- ترتیب سراسری میان پیام‌ها تضمین نشده است؛ تطبیق باید بر اساس شناسه پیوند و بازه اعتبار انجام شود.
- مقصد B03 فقط `Integration:Events:B03` است؛ کلید اختیاری `Integration:EventKeys:B03` است و در نبود آن `Integration:OutboundApiKey` استفاده می‌شود.
- اگر مقصد اختصاصی تنظیم نشده باشد، پیام در `Shared.OutboxMessage` باقی می‌ماند و به Receiver عمومی B05/B07 ارسال نمی‌شود.
- در این مرحله Inbox مصرف‌کننده B03 ایجاد نشده است.

## مواردی که هنوز قرارداد ندارند

پیام‌های تأیید/اجرا برای `PropertyStructureChange` تعریف نشده‌اند؛ زیرا منابع موجود فقط مقادیر عددی مجاز `ChangeType`، `ChangeStatus`، `OperationType`، `ItemRole` و `ExecutionStatus` را مشخص می‌کنند، اما معنای کسب‌وکاری و نمودار انتقال معتبر را تعیین نمی‌کنند. تا زمان دریافت تعریف رسمی، انتشار انتقال‌های حدسی امن نیست.
