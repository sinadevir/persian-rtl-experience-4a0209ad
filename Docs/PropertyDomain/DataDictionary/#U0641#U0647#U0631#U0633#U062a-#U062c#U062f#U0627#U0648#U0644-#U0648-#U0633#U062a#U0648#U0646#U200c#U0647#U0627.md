# فرهنگ داده ـ فهرست جداول و ستون‌ها

> این سند از اسکریپت Baseline یکپارچه، Migrationهای نسخه 11.8 و نگاشت `PropertyDomainDbContext` استخراج شده است. نام‌های فنی عین منبع باقی مانده‌اند. شرح‌های فارسی صرفاً دسته‌بندی ساختاری‌اند و جایگزین تعریف رسمی معنای کسب‌وکاری هر فیلد نیستند.

## ۱. دامنه و شمارش

- تعداد `DbSet`های تعریف‌شده در `PropertyDomainDbContext`: **74**.
- تعداد نگاشت‌های `ToTable` در EF Core: **74**.
- تعداد جدول‌های `CREATE TABLE` در Baseline یکپارچه: **68**.
- تعداد جدول‌های `CREATE TABLE` در کل Baseline و Migrationهای موجود: **74**.
- نام قیدهای Primary Key، Unique، Foreign Key، Check، Default و فهرست‌های صریح ایجادشده در DDL/Migration نیز در بخش هر جدول درج شده‌اند.
- شش جدول افزوده‌شده در Migrationهای B01/B04 در Baseline اولیه وجود ندارند و از طریق Migration ساخته می‌شوند؛ این موارد در فهرست زیر با منبع Migration مشخص شده‌اند.
- جدول‌های `Shared.OutboxMessage`، `Shared.InboxMessage` و `Shared.CommandReceipt` زیرساخت مشترک هستند، نه مالکیت یک ماژول دامنه.
- برای اعمال واقعی ساختار جاری، Baseline و Migrationهای متناسب باید به ترتیب و روی پایگاه داده هدف اجرا شوند؛ این سند به‌تنهایی Migration اجرا نمی‌کند.

## ۲. نگاشت ماژول به Schema

| Schema | حوزه |
|---|---|
| `B01` | هویت و اطلاعات پایه اشخاص |
| `B02` | ثبت مالکیت، نسخه‌های وضعیت مالکیت، حقوق و سوابق تصرف |
| `B03` | ملک، نشانی و ساختار فیزیکی ملک |
| `B04` | بخش‌های کاربری، طبقه‌بندی، شواهد، تخصیص‌ها و گردش تغییر کاربری |
| `B05` | مشترک، ارتباط مشترک با اشخاص، وضعیت، ثبت‌نام، طبقه‌بندی و محدودیت‌ها |
| `B06` | انواع رابطه و مجوز، رابطه، دامنه مجوز، پرونده و اختلاف |
| `B07` | پرونده چرخه عمر، درخواست تغییر اطلاعات و Timeline |
| `Shared` | زیرساخت پیام‌رسانی Outbox، Inbox و رسید فرمان |

## ۵. ملاحظات نگهداری

- ستون‌هایی که در Baseline ایجاد و سپس با `ALTER TABLE ... ADD` توسعه یافته‌اند، در فهرست همان جدول ادغام شده‌اند؛ منبع افزودن آن‌ها Migration است.
- این نسخه، فهرست نوع SQL و تهی‌پذیری را ارائه می‌کند؛ معنای دامنه‌ای ستون‌ها باید در README ماژول و قراردادهای Use Case تعریف شود. از روی نام ستون نباید سیاست کسب‌وکاری جدید استنتاج کرد.
- برای تغییر ساختار، ابتدا Migration رسمی را بررسی کنید؛ ویرایش مستقیم Baseline بدون بررسی اثر آن بر پایگاه داده‌های موجود مناسب نیست و باید با مسیر ارتقای نسخه هماهنگ شود.
- کلیدهای اصلی، خارجی، Check Constraint و Indexها در DDL منبع قرار دارند؛ برای ممیزی قیود هر جدول به DDL و Migration مربوط رجوع کنید. این سند خلاصه ستون‌هاست و جایگزین اسکریپت SQL نیست.
- تعدادها و فهرست‌ها در بازبینی بعدی باید با `PropertyDomainDbContext`، Baseline و همه Migrationهای اعمال‌شده تطبیق داده شوند.
